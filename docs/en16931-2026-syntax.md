# EN 16931:2026 Three-Way Field Mapping: UBL Invoice / UBL Credit Note / CII D25A

Source: CEN/TS 16931-3-2:2026 (UBL) and CEN/TS 16931-3-3:2026 (CII), draft versions for Formal Vote.

The mapping is taken from the normative "semantic model to syntax elements" tables:
Table 10 (UBL invoice) and Table 12 (UBL credit note) of Part 3-2, Table 10 (CII) of Part 3-3.
The UN/EDIFACT binding (Part 3-4) is not covered.

For the previous edition see [en16931-2017-syntax.md](en16931-2017-syntax.md).

## Syntax Versions

| Syntax | 2017 edition | 2026 edition |
|--------|--------------|--------------|
| UBL | 2.1 (ISO/IEC 19845:2015) | **2.5** — "only UBL 2.5 and any subsequent UBL 2.x version have all syntax elements which are needed for EN 16931-1:2026" |
| CII | D16B | **D25A** — "only CII D25A and any subsequent Dxxx version have all syntax elements which are needed" |

Specification identifier (BT-24) of a conformant instance: `urn:cen.eu:en16931:2026`.

## Namespaces

| Prefix | Namespace |
|--------|-----------|
| `cac` | `urn:oasis:names:specification:ubl:schema:xsd:CommonAggregateComponents-2` |
| `cbc` | `urn:oasis:names:specification:ubl:schema:xsd:CommonBasicComponents-2` |
| `rsm` | CII root — see note below |
| `ram` | CII Reusable Aggregate Business Information Entity — see note below |
| `udt` | CII Unqualified Data Type — see note below |
| `qdt` | CII Qualified Data Type — see note below |

Note: neither Part 3-2 nor Part 3-3 declares namespace URIs; only the prefixes above appear in the
XPaths. The UBL namespaces are unchanged from UBL 2.1. The CII namespace URIs are release-specific
(D16B used `urn:un:unece:uncefact:data:standard:CrossIndustryInvoice:100` and siblings, but the
`QualifiedDataType` URI in particular has differed between releases) and must be taken from the
D25A schema release rather than assumed.

## Conventions

- CII paths are relative to `/rsm:CrossIndustryInvoice`
- UBL Invoice paths are relative to `/Invoice`
- UBL Credit Note paths are relative to `/CreditNote`
- Within a `BG-*` section, paths are relative to the base path given under the heading; a path
  printed in full (starting with `/`) lies outside its group's base path, as specified in the source
- `(same)` means the Credit Note path is identical to the Invoice path after the element renames
  listed in [Key Differences](#key-differences-between-ubl-invoice-and-ubl-credit-note)
- `—` means the syntax has no element for that business term
- `\|` between two paths means the source offers **alternative** XPaths
  (BT-41, BT-56, BT-84, BT-90, BT-90-1, BT-91, BT-149, BT-150, BT-161)
- `Card.` is the cardinality of the semantic model, not of the syntax
- Sections follow the order of the semantic model as printed in the source, not BG number — the
  business groups added in 2026 (BG-33 … BG-39) appear at their semantic position
- Notes are condensed from the source's "Discrepancy and resolution" column; the formal mismatch
  codes (SEM-*, STR-*, CAR-*, SYN-*) are omitted here and remain in the source documents

## Key Differences Between UBL Invoice and UBL Credit Note

In the 2026 edition the credit note binding is a purely mechanical rename of the invoice binding:
after the five substitutions below, all 305 XPaths of clause 4.6 are identical to those of clause 4.5.
The structural deviations of the 2017 edition (BT-9, BT-11) have been removed.

| Substitution | Affects |
|--------------|---------|
| `/Invoice` → `/CreditNote` | every path (root element) |
| `cac:InvoiceLine` → `cac:CreditNoteLine` | BG-25 and its 88 descendants |
| `cac:CollectionInvoiceLine` → `cac:CollectionCreditNoteLine` | BG-34, BT-179, BT-179-1, BT-180 |
| `cbc:InvoicedQuantity` → `cbc:CreditedQuantity` | BT-129, BT-130 |
| `cbc:InvoiceTypeCode` → `cbc:CreditNoteTypeCode` | BT-3 |

Remaining non-path differences:

| ID | Difference |
|----|-----------|
| BT-9 | Credit note requires UBL 2.2 — `/CreditNote/cbc:DueDate` did not exist in UBL 2.1 (2017: `cac:PaymentMeans/cbc:PaymentDueDate`) |
| BT-11 | Credit note requires UBL 2.2 — `/CreditNote/cac:ProjectReference` did not exist in UBL 2.1 (2017: `cac:AdditionalDocumentReference/cbc:ID`) |
| BG-31 | Effective cardinality `1..1` (invoice) vs `0..1` (credit note) |
